# Security Policy

This repository ships five command-line tools (Hangman, Portfolio Tracker, File
Organizer, Terminal Assistant, Inventory Manager) and the shared modules they
import. They are portfolio software for the Datheon Python Programming
Internship (Credential ID `DT-2026-O6Q0X`), but they are installable software
too: `pip install -e .` puts five commands on your `PATH`, and a bug in the
dataset loaders reads files you point them at. That is enough of an attack
surface to deserve a written policy rather than an issue thread.

## Supported versions

Only the current release line receives security fixes. Anything older is
supported by upgrade, not by patch.

| Version | Supported | Notes |
| --- | --- | --- |
| 1.1.x | ✅ Yes | Current release line — fixes land here first. |
| 1.0.x | ⚠️ Critical only | Superseded by 1.1.0; upgrade before reporting. |
| < 1.0 | ❌ No | Pre-release development history. |

The version in `pyproject.toml` is the source of truth, and
`tools/community_health.py` fails the build when this table stops naming it — a
support matrix that is one release stale tells a reporter their bug is out of
scope when it is not.

## Reporting a vulnerability

**Do not open a public issue for a security problem.** A public issue is a
disclosure, and it is indexed before there is a fix.

Use GitHub's private vulnerability reporting, which is enabled for this
repository:

1. Open <https://github.com/krishsharma-code/Datheon_Python_Internship/security/advisories/new>.
2. Describe the issue using the "What to include" list below.
3. Submit. The report is visible only to you and the maintainer until an
   advisory is published.

If private reporting is unavailable to you, contact the maintainer
(`@krishsharma-code`) through GitHub and ask for a private channel before
sending details. Please do not attach proof-of-concept files to a public issue,
a pull request or a discussion thread.

### What to include

- The affected version (`hangman --version`, or the commit hash).
- The command or module involved, and the smallest input that triggers it.
- What an attacker gains: code execution, file read outside the target
  directory, credential exposure, denial of service.
- Whether the issue is already public anywhere.
- Your preferred name and link for the advisory acknowledgement, if you want
  one.

### What to expect

| Stage | Commitment |
| --- | --- |
| Acknowledgement of the report | Within 3 business days. |
| Initial assessment (severity, scope, affected versions) | Within 10 business days. |
| Fix for a high or critical issue | Target 30 days from acceptance. |
| Fix for a low or moderate issue | Next scheduled release. |
| Public advisory | Published after a fixed release is available, coordinated with you. |

If a report is out of scope, you get that answer with the reasoning inside the
assessment window rather than silence.

## Scope

**In scope** — defects in code this repository ships:

- The five tools under `projects/` and their CLIs.
- The shared modules at the repository root (`dataset_loader`, `validators`,
  `persistence`, `caching`, `logging_config`, `observability`, `errors`).
- The `datheon` package: console-script shims and entry points.
- The build and release tooling under `tools/` when it can affect what ships.

**Out of scope** — report these elsewhere, or not at all:

- Vulnerabilities in third-party dependencies. Report them upstream; tell us
  only if this repository's usage makes the impact worse.
- Anything that needs the attacker to already have the user's account, shell or
  physical access.
- Social engineering, spam, and reports generated by a scanner with no
  demonstrated impact.
- Denial of service from deliberately enormous input. The tools read files the
  user names and are not hardened against a multi-gigabyte argument; that is a
  documented limit, not a vulnerability.

## Handling of secrets

No token, key or credential belongs in this repository, and none is needed to
run it: the five tools are standard-library only, and the optional live-price
lookup reads its credentials from the environment. If you find a committed
credential, report it privately using the process above and **do not** open a
pull request that removes it — the value stays in the history either way, and
the fix is to rotate it, which only the owner can do.

## Safe harbour

Good-faith security research is welcome. If you follow this policy — report
privately, avoid privacy violations and data destruction, do not degrade the
service for other users, and give us reasonable time to fix before disclosing —
then we will not pursue or support legal action against you, and we will say so
publicly if anyone asks. Testing against your own installation is always fine.

## Attribution

Reporters who want credit are named in the published advisory and in
`CHANGELOG.md`. Reporters who prefer to stay anonymous stay anonymous.
